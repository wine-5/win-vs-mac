# ゲームパッド対応 設計

すべての操作をゲームパッドだけで完結できるようにするための設計。
「ラッパーを用意する」だけでは足りず、**キーボード／マウス前提で書かれた箇所を
ゲームパッドでも成立する形へ作り替える**必要がある。その洗い出しと方針をここへまとめる。

---

## 1. 現状の棚卸し

### 1.1 用意済みのもの

| 場所 | 内容 |
|---|---|
| `core/input/GamePadCode.h` | 左スティックXY・ボタンA/B・十字キーのみ |
| `IInputProvider` | `isPadButtonDown` / `getPadAxis` / `isPadConnected` の3つ |
| `InputManager` | DxLib の `GetJoypadInputState` / `GetJoypadAnalogInput` で実装 |
| `InputSystem` | 移動・ジャンプ・攻撃だけパッド対応済み |
| `UiInputMapper` | `UiAction` という意図の抽象化まで用意済み（**割り当てはキーボードのみ**） |

### 1.2 いま埋まっていない穴

1. **右スティックが取れない** → 視点操作がパッドで一切できない
2. **パッドにエッジ検出（押した瞬間）が無い** → 開閉トグル（Esc / E / F2）が実装できない
3. **パッドだけスナップショットを取っていない** → キーボードは `captureFrameInput()` で
   フレーム内の値を固定しているのに、パッドは毎回 DxLib を直接叩いており設計が揃っていない
4. **マウスポインタ前提の画面**（タイトル・インベントリ）にフォーカス移動の概念が無い
5. **セレクト／リザルト画面が Win32 の別ウィンドウ**（WebView）で、パッド入力が届かない


### 1.2.1 パッドの取得経路（重要）

DxLib のパッド取得には2系統ある。

| API | 取れるもの | 見えるパッド |
|---|---|---|
| `GetJoypadXInputState` | ボタン16個・両トリガー（0〜255）・両スティック（±32768） | **XInput 対応のみ**（Xbox系）。非対応パッドでは -1 |
| `GetJoypadDirectInputState` | 6軸・POV 4つ・ボタン32個（±1000） | DirectInput で見える全て（DualShock 4 / DualSense を含む） |

現行の `InputManager` が使っている `GetJoypadInputState` / `GetJoypadAnalogInput` は
左スティックとボタン数個しか返さないため、**どちらへ寄せるにしても差し替えが要る**。

そして**素の DualShock 4 / DualSense は Windows では XInput デバイスとして見えない**。
DS4Windows や Steam Input を挟めば Xbox パッドに化けるが、化けた先にジャイロは無い。
開発機のパッドが DualShock 4 である以上、**DirectInput 経路は必須**になる。

したがって2系統を両方持ち、`GamePadCode` の抽象へ寄せる。

- Xbox 系 … `GetJoypadXInputState`
- DualShock 4 / DualSense … `GetJoypadDirectInputState` ＋ 機種プロファイル
- ジャイロ … Platform 層へ HID 直読みを別途追加（4章・最後の段）

DualShock 4 の DirectInput での並び（Windows 標準ドライバ）:

| 添字 | ボタン | | 添字 | ボタン |
|---|---|---|---|---|
| 0 | □ | | 7 | R2 |
| 1 | × | | 8 | SHARE |
| 2 | 〇 | | 9 | OPTIONS |
| 3 | △ | | 10 | L3 |
| 4 | L1 | | 11 | R3 |
| 5 | R1 | | 12 | PS |
| 6 | L2 | | 13 | タッチパッド |

軸は `X`/`Y` が左スティック、`Z`/`Rz` が右スティック。
**十字キーはボタンではなく POV ハット**（0=上・9000=右・18000=下・27000=左）なので、
XInput 経路とは別に POV を方向へ展開する処理が要る。

### 1.3 実装中に見つかった不具合（対応時に併せて直す）

| 箇所 | 内容 |
|---|---|
| `InputSystem.cpp` | `input.m_moveZ = axisY` … DxLib は下方向が正。スティックを上に倒すと後退する |
| 同上 | `if (axisX != 0.0f)` … デッドゾーン無し。スティックの微小ドリフトでキーボード入力が毎フレーム上書きされる（浮動小数の完全一致比較） |
| `GamePadCode.h` | `ButtonA // 攻撃（〇）` `ButtonB // ジャンプ（×）` … DxLib の `PAD_INPUT_A/B` は Xbox 配置の A/B。結果として **A=攻撃・B=ジャンプ** となり、A=ジャンプという慣習と逆 |
| `InputManager` | 斜め入力の大きさが未正規化（キーボード斜めは 1.41、スティックは 1.0） |

## 2. 割り当て表

物理ボタン名は **Xbox 配置**で書く（DxLib の XInput 取得がこの並びのため）。

### 2.1 インゲーム操作

ボタン名は **PlayStation 表記**を主、Xbox 表記を括弧で併記する。
（DxLib から取るのは XInput の並びなので、実装側の識別子は Xbox 表記になる）

| 操作 | 現在（キーボード／マウス） | ゲームパッド | 種別 |
|---|---|---|---|
| 移動 | WASD / 矢印キー | 左スティック ＋ 十字キー | |
| 視点 | マウス移動 | **右スティック**（＋ジャイロ・設定で ON/OFF） | 新規 |
| ジャンプ | Space | **×**（A） | |
| 近接攻撃 | 左クリック | **〇**（B） | 連打・コンボ |
| 遠距離攻撃 | 右クリック | **R1**（RB）長押し | ため撃ち |
| ダッシュ | Shift | **L1**（LB）長押し ＋ 左スティック押し込み | 長押し |
| ステータス表示 | Tab | **SHARE**（View）長押し | 長押し |
| インベントリ開閉 | E | **△**（Y） | トグル |
| 端末で拡張子を付け替え | F2 | **□**（X） | トグル・端末の前でのみ |
| ポーズメニュー開閉 | Esc | **OPTIONS**（Menu） | トグル |

R2 / L2（RT / LT）と右スティック押し込みは空けておく。
回避や別の遠距離武器を足すときの置き場として残す。

### 2.2 UI 操作（`UiAction` へ割り当てを足すだけで全画面へ効く）

| `UiAction` | 現在 | ゲームパッド |
|---|---|---|
| NavigateUp / Down / Left / Right | 矢印キー / WASD | 十字キー ＋ 左スティック（リピートあり） |
| Confirm | Enter | **×**（A） |
| Cancel | Esc | **〇**（B） |

インゲームでは 〇 が近接攻撃、メニューでは 〇 がキャンセルになるが、
メニューが開いている間はゲームが止まるので取り合いにはならない。
決定を × に置くのは、PC で多数派の Xbox 配列パッドで
「下のボタン＝決定」が共通の作法になっているため。

左スティックはアナログ値なので、しきい値でデジタル方向へ落としてから
既存のリピート処理へ流す。倒しっぱなしでの往復を防ぐためヒステリシスを付ける
（0.5 で成立、0.35 を割ったら解除）。

### 2.3 その他の画面

| 画面 | 現在 | ゲームパッド |
|---|---|---|
| BIOS（スキップ） | Esc | 〇 |
| ロックスクリーン（解除） | Space / クリック | × |
| バトル開始演出（送り） | Enter / Space / クリック | × |
| ポーズメニュー | `UiInputMapper` 済み | 自動で対応 |
| 設定パネル | `UiInputMapper` 済み | 自動で対応 |
| タイトル | **マウス専用** | フォーカス移動の追加が必要（3章） |

| セレクト／リザルト | **Win32 の別ウィンドウ（WebView2）** | JS へフォーカス指示を送る（3章） |

## 3. 作り替えが要る箇所

### 3.1 タイトル画面（`TitleView`）

いま `getHitAt(mouseX, mouseY)` でマウス座標から当たりを取り、クリックで確定している。
`Hit`（ThumbCpu / ThumbMemory / ThumbDisk / Settings / Exit / Start）は既に列挙されているので、
**これを順序付きのフォーカス列とみなし** `UiInputMapper` で移動、Confirm で確定させる。
マウスのホバーは従来どおり残し、どちらで触っても同じ `Hit` が選ばれる形にする。

### 3.2 インベントリの付け替え（`InGame::updateSwapSelection`）

#### 入り口を1つに寄せる（実装済み）

もともと △（E）が「見るだけ」、□（F2）が「付け替え」で、窓の見た目もほとんど同じだった。
端末の目の前に立っているのに △ を押すと**使えない方**が開き、
付け替えられること自体に気付けない。

そこで **端末の前で開いたときは、どちらのボタンでも付け替えできる状態で開く**
（`InGame::isNearRenameTerminal`）。間違った方の扉を無くしてしまうのが一番早い。

そのうえで2つの状態を見た目で分ける。

| | 見るだけ | 付け替えできる |
|---|---|---|
| 窓の枠 | 通常（淡い青灰） | **アクセント色の太枠** |
| 見出し | 「インベントリ」 | **「拡張子の付け替え」** |
| 見出しのアイコン | 黄 | **アクセント色** |
| 見出し下の区切り | 細い線 | **アクセント色の帯** |
| 右上の表示 | 「見るだけ」（薄い文字） | **「入れ替えできます」（塗りバッジ）** |

#### 操作の作り替え（未着手）


マウスのドラッグ＆ドロップ（押した瞬間に掴む・離した瞬間に置く）で作られている。
パッドには「押しっぱなしで運ぶ」が無いので、**掴む／置くの2段階**へ置き換える。

- × … 掴む（もう一度 × で、そのとき合わせている枠へ置く）
- 十字キー・左スティック … 枠の移動
- 〇 … 掴んだものを離す（取り消し）

`InventoryView` は `setSelection(cursorIndex, heldIndex)` と `setDragging` を既に持っているので、
表示側はほぼそのまま使える。足りないのは**マウス座標ではなく枠番号で動かす経路**
（`findSlotIndexAt` の代わりになる、グリッド上の上下左右移動）。

### 3.3 セレクト／リザルト画面

`ISelectWindowManager` が作る Win32 の別ウィンドウ（常時最前面）で、DxLib の入力ループの外にある。
ただし中身は全て `WebViewWindowBase` 上の **WebView2（HTML/JS）** で、
C++ から `postMessage` で JS へ値を送る経路が既にある。`web/common/` に共有の置き場もある。

そこで **OS のカーソルを合成で動かすのではなく、フォーカス移動の指示を JS へ送る**形を採る。

- C++（DxLib のループ側）でパッドを読み、`{"type":"pad","action":"..."}` を
  いま操作対象のウィンドウへ `postMessage` する
- `web/common/pad-nav.js`（新規・全ページ共通）が受け取り、
  ページ内のフォーカス可能な要素を順に移す／`click()` する
- ウィンドウをまたぐ移動は `Win32SelectWindowManager` が順序を持ち、LB / RB で切り替える

OS のカーソルを合成（`SendInput`）で動かす案は採らない。ゲームがフォーカスを失った瞬間に
**他のアプリへ入力が漏れる**ためで、これは過去に実際に起きている。

### 3.4 対象外

- `ui::Button` … どこからも使われていない（`TitleView` は自前で描いている）。触らない

## 4. 実装の順序

土台 → 割り当て → 画面ごとの作り替え、の順に積む。1段ごとにコミットする。

- [x] 1. **`GamePadCode` を整理**
   … ×〇□△・L1/R1・L2/R2・両スティック・押し込み・OPTIONS/SHARE・十字キー
- [x] 2. **`InputManager` を2系統の取得へ差し替え**
   … `GetJoypadXInputState` と `GetJoypadDirectInputState`（DualShock 4 プロファイル・POV 展開）
   ＋ フレームスナップショット・デッドゾーン・軸の符号是正
- [x] 3. **`IInputProvider` へエッジ検出を追加**（`isPadButtonPressed` / `consumePadPress`）
- [x] 4. **`UiInputMapper` へパッドの割り当てを足す** … ポーズ・設定がここで対応完了
- [x] 5. **`InputSystem` の割り当てを 2.1 の表へ揃える**
- [x] 6. **`CameraSystem` へ右スティックの視点操作を足す**（4.1）
- [x] 7. **開閉トグル（ポーズ・インベントリ・端末）へパッドのボタンを足す**
- [ ] 8. **タイトルのフォーカス移動**（3.1）
- [ ] 9. **インベントリの掴む／置く**（3.2）
- [ ] 10. **セレクト／リザルトの `pad-nav.js`**（3.3）
- [x] 11. **操作ガイドの表示切り替え**（4.2）… インゲーム分は済。タイトル・ポーズ・設定は 8 と一緒に
- [ ] 12. **ジャイロ**（4.3）… ここまででパッドだけでゲームループが回る状態にしてから足す

7 まで済んだ時点で、**インゲームはパッドだけで遊べる**（移動・視点・攻撃・ジャンプ・
ダッシュ・ステータス・インベントリ開閉・端末・ポーズ）。8 以降へ進む前に、
DirectInput のボタンの並びと軸の向きを実機（DualShock 4）で確かめること。
ここが違っていると 8 以降が全て狂った前提の上に積み上がる。

### 4.1 視点操作の注意

マウスは「移動量（ピクセル）」、スティックは「速さ（倒し量）」で、性質が違う。
スティックぶんは `倒し量 × 回転速度 × deltaTime` で足し込む。
マウスの感度設定（`ControlSettings::sensitivityPerPixel`）をそのまま掛けると
フレームレートで速さが変わるので、**同じ段階値から別の係数を作る**
（`sensitivityPerSecond`・ラジアン/秒）。スライダーは1本のままで、
マウスとパッドで換算だけが違う形にする。上下反転（`m_invertY`）は共通。

倒し量はそのまま使わず、デッドゾーンを抜いた分を 0〜1 へ引き伸ばしてから
指数カーブ（2乗程度）を掛ける。線形のままだと、細かく狙う領域が無くなる。

### 4.2 最後に触ったデバイスの記憶

`IInputProvider::getLastInputDevice()` が持つ（`core::input::InputDevice`）。
`InputManager` がフレーム頭のスナップショットから毎フレーム決める。

- パッドのボタンかスティックが動いていれば `GamePad`
- そうでなく、キーが押されている／マウスが動いた／マウスのボタンが押されていれば `KeyboardMouse`
- どちらも無ければ**直前の値を保つ**（手を止めただけで表記が戻らないように）

パッドを先に見るのは、パッドで遊んでいる最中に机の上のマウスがわずかに動いただけで
表記が戻ってしまうのを避けるため。マウスの微動は 3px のしきい値で捨てる。

案内の表記はこれを見て出し分ける。ボタンの記号は `game::ui::PadButtonIcon` が
図形で描く（×は線2本・〇は円・□は角丸・△は線3本）。文字のフォントに頼ると、
小さくしたときに 〇 と □ が潰れて見分けられない。

`UiInputMapper` の「マウスが動いたらフォーカス枠を消す」も、いずれこれに寄せてよい。

### 4.3 ジャイロ（最後の段）

DxLib の経路では取れないため、Platform 層へ HID 直読みを1本足す。

- `SetupDiGetClassDevs` で VID `0x054C` の HID を探す（DualShock 4 は PID `0x05C4` / `0x09CC`）
- USB は入力レポート `0x01`（64 バイト）、Bluetooth は `0x11`（先頭が2バイトずれる）
- 角速度3軸は int16 のリトルエンディアン。静止しているときの平均を引いてドリフトを補正する
- 見つからなければ何もしない。パッドが無い環境・Xbox パッドでも落ちない形にする
- 設定画面（操作ページ）へ **ジャイロ ON/OFF と感度**を足す。
  既定は OFF。右スティックとは足し算にして、スティックで大きく回して
  ジャイロで微調整する使い方ができるようにする
