## 1. 試遊フィードバックによる改善点

社会人の方に遊んで頂いて挙がった改善点をまとめたもの。

### 1-1. 影がなく自分の位置が分かりにくい

- [ ] 自分の位置が分かるように**丸影**を付ける（プレイヤー・敵・弾）
- [ ] 就職作品として技術力を見せるなら**シャドウマップ**まで踏み込むか判断する（DxLibの `SetUseShadowMap` 系を使うか自前かも含めて）
- [ ] 影を入れたあとにジャンプ・着地・段差の見え方が改善されたか実機で確認する

### 1-2. インゲームの速度感が物足りない

- [ ] プレイヤーの移動速度・ダッシュ速度を上げる
- [ ] 敵の移動速度を上げる（プレイヤーだけ速いと追いつかれない／逃げ切れる問題が出るので同時に見る）
- [ ] 速度を上げたあとにカメラ追従・攻撃レンジ・索敵範囲が破綻しないか確認する

### 1-3. コントローラーだけでは遊べない

- [ ] **ダッシュ**をパッドに割り当てる（現状 `InputSystem` はパッドで移動・攻撃・ジャンプのみ）
- [ ] **遠距離攻撃**をパッドに割り当てる（現状マウス右クリックのみ）
- [ ] **カメラ操作**を右スティックに対応させる（現状マウスのみでパッドだけでは視点が動かせない）
- [ ] ステータス表示（Tab）・ポーズ（Esc）などUI系操作もパッドから触れるようにする
- [ ] セレクト画面・タイトル・リザルトなど**インゲーム外のUIもパッドで操作**できるか確認する
- [ ] ボタン配置を決めて操作説明（README・ルール説明パネル）へ反映する

### 1-4. ファイル選択への警戒でそもそも遊ばれない恐れ

- [ ] **デモ動画をポートフォリオの主導線に置く**（遊ばれない前提で、動画だけで内容が伝わる構成にする）
- [ ] ファイル選択が「どこかにアップロードされるのでは」と警戒される点への説明を用意する
  - [ ] READMEと起動時（またはセレクト画面）に「ファイルは読み取りのみ・送信しない」旨を明記する
  - [ ] 実際に何を読んでいるか（拡張子・サイズ・更新日時など）を明示する
- [ ] ファイル選択せずに遊べる**デモ用のダミーフォルダ／サンプルモード**を用意するか検討する
- [ ] Windows Sandbox で動くか（隔離環境でも起動・プレイできるか）を確認しておく

### 1-5. 起動演出の世界観がインゲームまで続いていない

- [ ] 起動時のデスクトップ演出は評価が高かったので、**その驚きをインゲームまで引っ張る**方向を検討する
  - [ ] 「デスクトップ画面のまま敵が出てきて戦う」ような見せ方が現実的か検討する（背景をデスクトップにする・UIをOSのウィンドウ風にする等、コストの低い方向から）
  - [ ] インゲームの背景・プロップを「フォルダの中」からもう一段OSらしく寄せる
- [ ] Windows と Mac の対立構造をもっと分かる形で提示する（導入のテキスト・ボスの立ち位置・UIの色味）

### 1-6. 攻撃に硬直（隙）がなく駆け引きが成立していない

- [ ] **攻撃中の硬直（隙）**を入れる：攻撃モーション中に通常と同じ移動操作ができないようにする
- [ ] ビタ止まりにせず、攻撃開始時の移動ベクトルを少し残して**滑らせる**（踏み込みの演技）
- [ ] 攻撃アクションごとの**メリット／デメリット**を整理して駆け引きを成立させる（強攻撃は隙が大きい・弱攻撃は隙が小さい等）
- [ ] 敵側にも同様に硬直・予備動作を入れて、避ける／差し込む余地を作る

### 1-7. プレイヤーを誘導する導線がない

- [ ] プレイヤーを進ませたい方向へ**目を引くオブジェクト**を置いて誘導する（世界観に合わせて「光るオブジェクト」など）
- [ ] 注目してほしいギミック・オブジェクトが自然に目に入る配置にする
- [ ] 初見のプレイヤーが迷わずボスまで辿り着けるかを確認する

## 13. オンラインランキング（余裕があれば）

難易度ごとのクリアタイムを全プレイヤー共通で集計し、上位3位を表示する。工数目安 2〜3日。

### 構成

- **バックエンド**：Supabase（無料枠 / PostgreSQL）。テーブルを作るとREST APIが自動生成されるのでサーバー側のコードは書かない
- **通信**：WinHTTP（Windows標準。追加DLL・vcpkg不要）
- **JSON**：`thirdparty/nlohmann/json.hpp`（導入済み）
- **表示**：WebView2（`WebView2Host` / `ResultWindow` を流用）

テーブルは `scores(id, player_name, difficulty, time_ms, created_at)` の1つのみ。
取得は `GET /rest/v1/scores?difficulty=eq.hard&order=time_ms.asc&limit=3`。

追加するファイルは `core/interface/IRankingService.h`（インターフェース）／`platform/network/WinHttpClient.*`（GET・POST）／`infrastructure/network/RankingClient.*`（JSON組み立て・パース）。Game層は `IRankingService` のみに依存させる。

### タスク

- [ ] `IRankingService` を定義し、まずローカルJSON実装で動かす（後からリモート実装へ差し替え）
- [ ] Supabaseプロジェクト作成 + テーブル作成
- [ ] RLS設定（INSERTのみ許可・UPDATE／DELETE不可）
- [ ] `WinHttpClient` 実装
- [ ] `RankingClient` 実装（スコア送信・上位3件取得）
- [ ] 非同期化（`std::thread` + `std::future`、毎フレームポーリング → EventBusで通知）
- [ ] リザルト画面にランキング表示（WebView）
- [ ] プレイヤー名入力（文字数制限・NGワード）
- [ ] オフライン・通信失敗時もゲームが継続できることを確認

### 注意点

- **通信をゲームループ内で同期呼び出ししない**（必ずフリーズする）
- 通信失敗でゲーム進行を止めない。「送信中…」「通信失敗」の状態を持たせる
- 書き込みキーをexeに直接埋め込まない。権限はRLSでサーバー側に寄せる
- 不正タイム対策は「明らかに不可能な短さを弾く」程度で十分
