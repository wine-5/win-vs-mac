## 7. 追加開発（7/26 追加）

着手順は **7-1（非同期）→ 7-2（Loading UI）** の依存関係を厳守。非同期化しないとLoading画面は実際には動かないため、UIを先に磨いても確認できない。7-3と7-4は独立しているのでいつでも着手可。

### 7-1. 非同期ロードの追加（PF-A対処） — `feature/async-loading` ★★★

- [ ] 方式を決める：`SetUseASyncLoadFlag(TRUE)` 方式か、InGame構築の分割ロード方式か（performance_report_v2.md の PF-A 参照。応答なし回避だけなら分割ロード方式が単純）
- [ ] Loading シーンの update で進捗を監視し、完了後に InGame へ遷移する流れに変更
- [ ] ロード中も毎フレーム `ProcessMessage` ＋ `ScreenFlip` に戻ることを確認（ウィンドウドラッグで固まらないこと）
- [ ] 重いフォルダ（HARD相当）でロード中の応答性を実機確認
- [ ] MemoryProbe で修正前後のピークメモリが悪化していないことを確認
- ※ 単独ブランチ必須。UI変更と混ぜない（不具合の切り分けができなくなる）

### 7-2. Loading画面のUI調整 — `feature/loading-ui` ★★

- [ ] 進捗表示（何を読んでいるか／進捗率）を非同期ロードの実際の進行と接続する
- [ ] Loading画面で **Ctrl + C からアプリケーションを終了**できるようにする（旧・リリース品質欄から移動）
- [ ] ロードが一瞬で終わる軽いフォルダでも表示が破綻しない（最低表示時間 or 即遷移の方針を決める）
- [ ] 通しでの見た目確認（1920×1080固定＋ボーダーレス）

### 7-3. ルール説明・Audio調整パネルの追加 — `feature/rules-audio-panel` ★★

- [ ] ルール説明パネル：表示する場所を決める（セレクトの RulesWindow 拡充か、ポーズメニューへの追加か）
- [ ] ルール説明の文面作成（操作・目的・拡張子ボーナスの説明。README刷新（6章）と文面を共用すると一石二鳥）

- [ ] 音量設定の保存方針を決める（セッション内のみか、ファイル永続化か。永続化するなら保存先とフォーマットを決める）
- [ ] パネル追加に伴うポーズメニューのレイアウト調整
- ※ Audio調整が設定の永続化まで含む規模になるなら `feature/audio-settings` として分割を検討

### 7-4. レベルデザイン — `feature/level-design` ★★★
